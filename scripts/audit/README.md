# Проверки аудита (scripts/audit)

Сквозные проверки к исправлениям октябрьского аудита. Это не юнит-тесты, а
сценарии против РАБОЧЕЙ копии API на тестовой базе: они создают тестовых людей,
деньги и файлы. **Не запускать на боевом сервере и боевой базе.**

## Как запускать

1. Поднять тестовую копию: Postgres, Redis (`:6380`), `node server/server.mjs`
   с переменными `RATE_LIMIT_PER_MINUTE=1000000`, `NODE_ENV=development`,
   `OWNER_USERNAME=ownertest`, `EMAIL_MODE=log`; журнал сервера писать в файл
   `<каталог>/api.log` — из него тесты достают коды входа.
2. `node scripts/audit/<файл>.mjs <каталог>` (каталог с `api.log`).
   Базу тесты находят по `TEST_DATABASE_URL` (по умолчанию `postgres://sky:sky@127.0.0.1/sky`),
   нужен клиент `psql`.

| файл | что проверяет |
|---|---|
| `avatar-test` | аватар: слишком большой не стирает прежний (400), чужой профиль не меняется |
| `lnotif-test` | уведомления курьера: форма данных, изоляция, чужое не прочитать, `null`-тело |
| `media-sec` | кино / SkyVideo / музыка: Range, HEAD, чужой доступ, подделка пропуска, удаление, подмена типа |
| `abort-test` | оборванная загрузка не оставляет запись и резерв квоты |
| `retention-test` | срок хранения личных файлов, «хранить всегда», уборка |
| `svid-test` | SkyVideo: просмотры, лайки, комментарии, монетизация, приватность |
| `garant-test` | Sky Garant: гонки подтверждений/решений/отмен — деньги ровно один раз |
| `ads-refund-test` | возврат бюджета рекламы ровно один раз |
| `wallet-test` | суммы, служебные типы, гонки списаний |
| `prime-gate-test` | Prime нельзя получить в обход |
| `ws-authz-test` | мессенджер по WebSocket: посторонний ничего не читает и не меняет |
| `rbac-test` | админские ручки закрыты для обычных и «только чтение» |
| `gameservers-test` | игровые серверы: права владельца/модератора/участника, закрытые, бан, голос, сообщения |
| `adminmoney-test` | админские деньги: баланс, откат операций, Prime с возвратом, отзыв подарков, отмена подписок, гонки |
| `push-test` | пуши: ключ, подписка/отписка (сервер с `VAPID_*`) |
| `rl-test` | пределы по IP считаются по реальному клиенту (запускать на сервере с `RATE_LIMIT_PER_MINUTE=20`, порт 8090) |
| `extract` → `sweep` → `fuzzall` | список ручек из кода; обход без входа / с обычным входом; фаззинг 5xx |

`media-integrity` (отчёт «записи без файлов») лежит в `scripts/media-integrity.mjs`
и читает боевую базу только на чтение.

## otpmock: коды SMS в сквозных тестах

`otpmock.mjs` — клиент тестового ящика (https://otpmock.com), `otpmock-sms-test.mjs` — вход по SMS через него.
API запускается с `OTPMOCK_URL=https://api.otpmock.com` и `OTPMOCK_API_KEY` (из окружения), тест — с теми же переменными.
Без них тест пропускается. Только тест/CI/staging: `docker-compose.otpmock.yml` (`-f docker-compose.yml -f docker-compose.otpmock.yml`), ручной workflow `otpmock-sms.yml`. Боевой compose не менялся.
