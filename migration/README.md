# Перенос Sky на другой сервер

Три скрипта и один zip. Всё остальное (код, база, файлы, ключи, настройки хоста) лежит внутри zip.

| Скрипт | Где запускать | Что делает |
|---|---|---|
| `pack.sh` | старый (рабочий) сервер | собирает **один zip**: база, все файлы (`/data`), `.env` и `secrets/`, настройки хоста, по желанию сертификаты, код Sky, счётчики для сверки |
| `upload.sh` | где лежит zip (старый сервер или ваш компьютер) | загружает zip на другой сервер **с докачкой** и проверяет sha256 после загрузки |
| `restore.sh` | новый сервер | достаёт из zip всё нужное, проверяет контрольные суммы, восстанавливает и **сверяет «без потерь»** |

Всё содержимое набора зашифровано age. **Секретный ключ age (`backup.key`) в zip нет** — храните его отдельно: без него zip не открыть
(публичный ключ — `BACKUP_AGE_RECIPIENT` в `.env`; создать пару — `bash scripts/install-backup.sh --genkey`).

## Порядок

1. **Старый сервер.** Для самой точной копии включите в админке «Технические работы» (никто не пишет в базу), затем:
   ```bash
   sudo apt install -y zip unzip age          # если нет
   sudo bash migration/pack.sh                # → /root/sky-migration/sky-migration-ДАТА.zip (+ .sha256)
   # с сертификатами:  --with-certs     без кода Sky:  --no-source     другой каталог:  --out /mnt/big
   ```
2. **Загрузка.**
   ```bash
   bash migration/upload.sh --to root@НОВЫЙ_IP --zip /root/sky-migration/sky-migration-ДАТА.zip
   # сразу с ключом и запуском восстановления:  --age-key backup.key --run
   ```
3. **Новый сервер** (чистая Ubuntu, root):
   ```bash
   bash /root/sky-migration/restore.sh --zip /root/sky-migration/sky-migration-ДАТА.zip --key /путь/backup.key
   ```
   Docker, если его нет, и код Sky (из `source.tar.gz` внутри zip — GitHub не нужен) ставятся сами.
4. **Проверка.** В `/etc/hosts` своего компьютера впишите IP нового сервера и домен — зайдите, откройте музыку, кино, чат, кошелёк.
5. **Переключение:** A-записи в DNS → новый IP; сертификат (если не переносили — `scripts/init-letsencrypt.sh`); службы хоста
   (`scripts/install-watchdog.sh`, `scripts/install-backup.sh --install`). Старый сервер не выключайте сутки.
6. **Уборка:** удалите `backup.key` и zip с нового сервера.

## Что значит «без потерь»

* Перед упаковкой снимаются счётчики: строк в **каждой** таблице, число и объём файлов в `/data` (`STATS.txt`).
* `restore.sh` останавливается, если хоть одна часть набора не сходится с `MANIFEST.txt`, и не пишет в непустую базу без `--force`.
* После восстановления счётчики снимаются заново. Если где-то **меньше**, чем было, — это потеря: она печатается красным, код выхода 3, DNS переключать нельзя.
  Больше — нормально (записи, появившиеся при упаковке); при упаковке в «Технических работах» цифры совпадут до единицы (`--strict` требует именно этого).

## Что в набор не входит

* Файлы в S3-хранилище (если `STORAGE_PRIMARY=s3`) — они остаются у хостера; новому серверу нужны те же ключи S3 (они внутри `config`).
* Образы Docker (собираются на новом сервере из кода) и сессии Redis (люди войдут заново — токены обновятся сами).
* DNS, файрвол и SSH-ключи хостера — настраиваются вручную.

## Если что-то пошло не так

* `restore.sh` ничего не ломает на старом сервере; на новом его можно запускать повторно (для непустой базы — с `--force`, понимая последствия).
* zip повредился при передаче — запустите `upload.sh` снова: докачает.
* «Ключ age не открывает набор» — не тот `backup.key`.
