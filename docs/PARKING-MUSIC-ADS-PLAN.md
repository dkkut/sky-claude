# Sky Parking + Sky Music Studio + Sky Ads — аудит и план (ноябрь-2026)

## Что уже есть в проекте (результат аудита)

| Область | Что найдено | Решение |
|---|---|---|
| Оплата | SkyKassa (`skykassa*.mjs`) — ПОПОЛНЕНИЕ кошелька (ручная проверка + партнёры). Все покупки в Sky списываются с кошелька (`wallet.spendIn`, одна транзакция со статусом). Прямой «карточной» оплаты заказа через SkyKassa нет. | Парковка оплачивается с кошелька Sky (пополняется через SkyKassa). Оплата и активация сессии — ОДНА транзакция под блокировкой заказа, повтор по `idem_key` не списывает дважды. Клиентскому «успеху» сервер не верит. |
| Деньги организациям | Распределения платежей между сторонами в Sky нет, договорных условий нет. | Платёж фиксируется в журнале; выплат организациям НЕТ (по ТЗ — только после договорных условий). В отчётах «оплачено» ≠ «прибыль». |
| Роли | `server/roles.mjs` (права Sky-админов), `admin.mjs`, `adminsec.mjs` (`logAdmin`, step-up), оргуровневые роли в модулях (kbiz, goorg, pvzops). | Новые права Sky: `parking`, `parking_moderation`. Роли внутри организации (владелец/администратор/модератор) — своя таблица, как у GO-организаций. |
| Карты | `maps.mjs` (Google/Яндекс), `SkyMap.tsx`, геокодер. | Парковки хранят координаты, показываются через `SkyMap`; карта без ключа — понятное состояние. |
| Автомобили | `go_cars` — одно авто на профиль (топливо). | Отдельная `parking_vehicles` (до 5 авто, номер зашифрован), в сессии хранится СНИМОК номера. |
| Карточки музыкантов | `music_artist_cards` (owner_id, merged_into, claim-процесс, `artistcards.mjs`), `music_tracks.artist_card_id`, `music_artists` (профиль-артист, не карточка). Один владелец на карточку, у человека может быть несколько. | Студия строится НА карточках (`music_artist_cards`), каталог не дублируется. |
| Треки | `music_tracks` (owner_id = загрузивший, статус, лицензия, текст, explicit…), файл под `musicstore.mjs`, `TrackEditor.tsx`. Версий аудио нет. | Версионирование аудио (`music_track_versions`), атомарная замена. Владелец карточки правит только свои (загруженные им) треки на карточке; чужие — только просмотр. |
| Роялти | Нет ни кода, ни таблиц. | Только безопасная основа: глобальный и индивидуальный переключатели + журнал; начислений не выдумываем. |
| Sky Ads | УЖЕ есть: `ads.mjs`, `routes/ads.mjs`, `src/ads/*`, кампании `ad_campaigns` (оплата с кошелька, модерация правом `content`, показы/клики, лимиты частоты), площадка `video_preroll`. | Расширяем существующий Sky Ads, второй системы не заводим: загрузка видео-креатива, обработка, показ между роликами в SkyVideo. |
| Видео | `skyvideo*.mjs`, `videostore.mjs`, плеер `SkyVideo.tsx`. | Реклама встраивается в переход «следующий ролик». |
| Уведомления | `giftnotify.notifyGift`, `staffnotify.notifyStaff`, push `pushToOffline`. | Используем их. |
| Журнал | `logAdmin`, `skylog.logEvent`, `auditlog.mjs`. | Админ-действия — в них; операции организаций — в `parking_events`. |

## Порядок работ (каждый шаг проверяется отдельно)

1. Parking A — модель данных (миграция 170), права, организации, парковки, тарифы, расчёт, модерация, ревизии (сервер + тесты).
2. Parking B — машины, заказы, оплата с кошелька, сессии, продление, возвраты, жалобы, уведомления, уборка (сервер + тесты).
3. Parking C — интерфейс (карта, карточка, оплата, сессия, история), кабинет организации, раздел админки.
4. Music Studio — выбор карточки, обзор, список треков, редактор, версии аудио и безопасная замена, оформление карточки.
5. Роялти — настройки артиста и глобальный переключатель в админке.
6. Админка карточек — список, передача владельца.
7. Sky Ads — видео-креатив, обработка, показ в SkyVideo, статистика.
8. Сквозные: уведомления, аудит, производительность, итоговый отчёт.
