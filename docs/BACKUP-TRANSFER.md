# Перенос резервного хранилища Sky на другой сервер

Внутренний документ (в образ не попадает). Скрипт: `scripts/backup-transfer.mjs`. Источник **никогда** не меняется и не удаляется.

## Что переносится
Копии Sky Storage: объекты `SBK1` (зашифрованы ключом KEK `STORAGE_KEK_<ID>`), манифесты, цепочка. Это содержимое цели `STORAGE_BACKUP_TARGET` (`s3` — отдельный бакет `STORAGE_BACKUP_S3_*` либо общий `STORAGE_S3_*`; `local` — каталог `STORAGE_BACKUP_DIR`).
Отдельно (хостовые копии `scripts/backup.sh`): файлы `*.gz.age`, `config-*.tar.gz.age` — см. шаг 6.

## Порядок
1. **До переноса.** Свежая копия есть, проверка восстановления проходила (`scripts/backup-verify.sh`). Запишите, где лежат ключи KEK и age-ключ (`scripts/secrets-export.sh`): **без них копии на новом месте не открыть**.
2. **Новое место.** Бакет S3 у другого хостера или каталог на отдельном томе нового сервера. Для `local` — том смонтирован и доступен API.
3. **План (ничего не меняет):**
   ```
   docker compose exec -T \
     -e NEW_BACKUP_TARGET=s3 -e NEW_BACKUP_S3_ENDPOINT=https://… -e NEW_BACKUP_S3_REGION=… -e NEW_BACKUP_S3_BUCKET=… \
     -e NEW_BACKUP_S3_ACCESS_KEY=… -e NEW_BACKUP_S3_SECRET_KEY=… -e NEW_BACKUP_S3_PREFIX=sky-backups/ \
     api node scripts/backup-transfer.mjs plan
   ```
   (для каталога: `-e NEW_BACKUP_TARGET=local -e NEW_BACKUP_DIR=/mnt/…`). Покажет, сколько объектов и байт будет скопировано.
4. **Копирование:** тот же запуск с `copy`. Докопирует недостающее или с другим размером; можно повторять — уже скопированное пропускается.
5. **Сверка:** `verify` — размер и SHA-256 каждого объекта с обеих сторон. «Копии идентичны» и код выхода 0 — только тогда переключаться.
6. **Хостовые копии:** `rsync -a --checksum --partial /opt/sky/backups/ user@новый:/opt/sky/backups/` затем на новом сервере `sha256sum -c`/`scripts/backup-verify.sh файл ключ`. Для регулярной отправки: `scripts/install-backup.sh --remote user@новый:/путь`.
7. **Переключение (отдельное осознанное действие, не автоматическое):** на боевом сервере `scripts/setup-storage.sh --backup-bucket` (новый бакет, проверка живым запросом) или правка `STORAGE_BACKUP_DIR`; затем `deploy-local.sh`. В админке Sky Storage → «Хранилище копий» убедитесь, что площадка «доступна», число и объём копий совпадают, сделайте пробную копию и «проверку восстановления».
8. **Старое место не удаляйте**, пока новое не отработало несколько расписаний копирования и не пройдена проверка восстановления. Затем — отзовите ключи доступа к старому бакету.

## Что не проверено
Копирование между `local → local` проверено на тестовых данных; пути `s3` используют тот же клиент, что и сама панель, но на настоящем S3 хостера из этой среды запуск не выполнялся. Скорость больших копий ограничена каналом; перенос идёт потоком (память не растёт), объекты крупнее одной части загружаются многокомпонентно.
