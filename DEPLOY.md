# Развёртывание Sky

Продакшн-стек: nginx (TLS, статика, проксирование) → API и WebSocket-хаб,
рядом PostgreSQL и Redis. Наружу открыты только 80 и 443.

Рассчитано на Ubuntu 24.04, 12 ГБ RAM, 160 ГБ SSD. Сервисы под лимитами
берут около 4 ГБ, остальное остаётся системе, сборке и запасу.

---

## Схема

```
        Интернет :80/:443
              │
        ┌─────▼──────┐
        │   nginx    │  TLS, заголовки безопасности, rate limit
        │   (web)    │  раздаёт dist/
        └─────┬──────┘
       /api/  │  /ws
        ┌─────▼──────┐
        │    api     │  HTTP :8080 + WebSocket :8081 (один процесс)
        └─────┬──────┘
       ┌──────┴───────┐
  ┌────▼────┐   ┌─────▼────┐
  │ postgres│   │  redis   │      внутренняя сеть, с хоста недоступны
  └─────────┘   └──────────┘
```

## Первый запуск

### 1. Настроить сервер

От root на свежей машине:

```bash
git clone https://github.com/dkkut/sky-claude.git /opt/sky
cd /opt/sky
sudo bash scripts/bootstrap-server.sh
```

Скрипт поставит Docker, заведёт пользователя `sky`, закроет SSH (только по
ключу, без root), поднимет UFW и fail2ban, включит автообновления
безопасности и сгенерирует `/opt/sky/.env` со свежими секретами.

> Скрипт **не** отключит вход по паролю, если у пользователя `sky` нет
> `authorized_keys` — иначе вы потеряете доступ. Добавьте ключ
> (`ssh-copy-id sky@сервер`) и запустите скрипт ещё раз.

Проверьте вход по ключу в **отдельном** терминале, не закрывая текущую сессию.

### 2. Направить домен

A-запись домена (и `www`) → IP сервера. Дождитесь обновления DNS:

```bash
dig +short ваш-домен.ru
```

### 3. Выпустить сертификат

```bash
cd /opt/sky
bash scripts/init-letsencrypt.sh
```

Сертификат берётся в режиме `--standalone` (порт 80 свободен, nginx ещё не
поднят), затем запускается весь стек. Дальше продление автоматическое:
контейнер `certbot` просыпается каждые 12 часов, nginx перечитывает
конфигурацию каждые 6.

Сначала стоит прогнать с `CERTBOT_STAGING=1` в `.env` — у Let's Encrypt лимит
5 выпусков в неделю на домен, и упереться в него на отладке легко.

### 4. Проверить

```bash
curl -I https://ваш-домен.ru/healthz     # 200
docker compose ps                         # все healthy
```

## Автоматический деплой

Пайплайн `.github/workflows/deploy.yml` собирает образы, кладёт их в GHCR и
раскатывает по SSH. Сервер тянет образы, исходники на него не попадают.

### Секреты репозитория

Settings → Secrets and variables → Actions:

| Секрет | Что это |
|---|---|
| `SSH_HOST` | адрес сервера |
| `SSH_USER` | пользователь деплоя (`sky`) |
| `SSH_KEY` | приватный ключ этого пользователя |
| `SSH_PORT` | порт SSH, если не 22 |
| `SSH_KNOWN_HOSTS` | вывод `ssh-keyscan сервер` — фиксирует ключ хоста |

Без `SSH_KNOWN_HOSTS` деплой пройдёт, но ключ сервера будет принят без
проверки — пайплайн об этом предупредит.

### Переменные (вкладка Variables)

| Переменная | По умолчанию |
|---|---|
| `APP_DIR` | `/opt/sky` |
| `DOMAIN` | нет; если задать — после деплоя проверяется `https://DOMAIN/healthz` |

Пайплайн запускается на push в ветку разработки и вручную. Сначала он
прогоняет `npm run build` (`tsc` + `vite`) — сломанный по типам код до
сервера не доедет.

## Эксплуатация

```bash
cd /opt/sky

docker compose ps                       # состояние
docker compose logs -f api              # логи API
docker compose logs -f web              # логи nginx
docker compose restart api              # перезапуск сервиса
docker compose exec web nginx -t        # проверить конфиг nginx

# бэкап базы
docker compose exec -T postgres pg_dump -U sky sky | gzip > backup-$(date +%F).sql.gz

# восстановление
gunzip -c backup-2026-01-01.sql.gz | docker compose exec -T postgres psql -U sky sky
```

Логи ротируются по 10 МБ, до 5 файлов на контейнер.

## Безопасность: что уже сделано

**Сеть.** Наружу открыты только 80 и 443. PostgreSQL, Redis и API живут во
внутренней сети Docker без выхода в интернет и с хоста недоступны — проверено.

**TLS.** Только 1.2 и 1.3, наборы шифров с прямой секретностью, HSTS на год.

**Заголовки.** HSTS, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`,
`Permissions-Policy`, `Cross-Origin-Opener/Resource-Policy` и CSP.

CSP выдана по факту того, что приложение реально делает: `'unsafe-inline'`
для стилей (React расставляет их через `style={{}}`), `blob:` для скриптов и
воркеров (песочница ботов), `blob:`/`data:` для картинок и медиа из IndexedDB.
**`'unsafe-eval'` не выдан** — приложение проверено в браузере на всех
модулях, нарушений нет.

**Лимиты запросов.** `/api/auth/` — 5 запросов в минуту с адреса (против
перебора паролей), остальное — 30 в секунду, не более 100 соединений с адреса.

**Хост.** SSH только по ключу, root-логин закрыт, UFW, fail2ban (3 попытки →
бан на сутки), автообновления безопасности, ужесточённые sysctl.

**Контейнеры.** API работает не от root, `no-new-privileges`, лимиты памяти,
у каждого сервиса healthcheck.

## Смена секретов

Если секреты из `.env` где-то засветились — попали в переписку, на
скриншот, в чужие руки, — их надо сменить. На сервере:

```bash
cd /opt/sky && bash scripts/rotate-secrets.sh
```

Скрипт меняет подписи токенов и пароли Postgres и Redis (пароль базы —
и в самой базе тоже, иначе новый в `.env` ничего не значит), заводит
недостающие переменные и спрашивает ключ отправки SMS. Старый `.env`
остаётся рядом резервной копией.

Все вошедшие после этого выходят из аккаунтов: подпись токенов сменилась.
Профили, деньги и переписка на месте.

## Отправка кодов

Коды нужны в двух местах: вход по номеру (SMS) и второй фактор по почте.
Пока провайдер не подключён, войти не сможет никто: режим `log` в бою
запрещён, потому что иначе любой, кто читает журнал контейнера, войдёт
под чужим аккаунтом.

**SMS через TextBee** — сообщения уходят с вашего же телефона на Android
(в приложении TextBee он работает шлюзом). В `/opt/sky/.env`:

```
SMS_MODE=textbee
SMS_API_ID=<ключ из личного кабинета TextBee>
SMS_DEVICE_ID=<нужен, только если телефонов подключено несколько>
```

**SMS через sms.ru** — если нужен обычный оператор рассылки:

```
SMS_MODE=smsru
SMS_API_ID=<ключ из личного кабинета sms.ru>
SMS_FROM=<имя отправителя, если согласовано с провайдером>
```

Другой провайдер подключается через свой обработчик — сервер шлёт ему
`POST {to, text}`:

```
SMS_MODE=webhook
SMS_WEBHOOK_URL=https://…
SMS_WEBHOOK_TOKEN=…        # уйдёт как Authorization: Bearer
```

**Почта.** Обычный ящик (в том числе у хостинга):

```
EMAIL_MODE=smtp
EMAIL_FROM=Sky <no-reply@ваш-домен>
SMTP_HOST=smtp.ваш-хостинг
SMTP_PORT=465              # 465 — сразу TLS; 587 — тогда SMTP_SECURE=false
SMTP_SECURE=true
SMTP_USER=no-reply@ваш-домен
SMTP_PASS=…
```

Письма уходят только по шифрованному соединению: без TLS сервер
отправлять откажется, а самоподписанный сертификат не примет — иначе
код мог бы прочитать кто-то посередине. Вместо SMTP можно указать
`EMAIL_MODE=resend` с `RESEND_API_KEY` или свой обработчик
(`EMAIL_MODE=webhook`).

После правки — `docker compose up -d api`. При запуске сервер сам
проверяет настройки и пишет в журнал, чего не хватает; строка
`[доставка] …` в логах означает, что коды дойдут не до всех или ни до кого.

Ограничения на отправку стоят и в приложении, и в nginx: код живёт
5 минут, между отправками пауза в минуту, на один номер не больше пяти
кодов в час (на почту — двенадцати), пять неверных попыток гасят код.

Номер приводится к международному виду до всего остального:
`+79001234567`, `89001234567` и `+7 900 123-45-67` — это один и тот же
Sky ID, а не три разных аккаунта.

## Закрытая бета

Пока приложение не готово, сайт закрыт ключом: без него не отвечает ни
одна ручка API, а не только экран входа — иначе калитку обошли бы, просто
не открывая страницу.

Завести ключи (на сервере, в `/opt/sky/.env`):

```bash
# по одному на каждого, кому нужен доступ
openssl rand -base64 24 | tr -d '/+=' | head -c 24; echo
```

Полученные строки записать через запятую, подпись после двоеточия — чтобы
понимать, чей ключ отзывать:

```
BETA_KEYS=Ab3xY...:мой,Qw9zT...:команда
```

Затем `docker compose up -d api`.

  * **Отозвать ключ** — убрать из строки и перезапустить API. Перестанет
    работать и сам ключ, и все выданные по нему пропуска.
  * **Закончить бету** — оставить `BETA_KEYS=` пустым и перезапустить API.
    Калитки не будет, сайт откроется всем. Код при этом трогать не нужно.

Ключ обменивается на подписанный пропуск в HttpOnly-куке на 30 дней:
вводить его каждый раз не придётся, а из браузера его не достать. В базе
лежит не сам ключ, а его HMAC — по дампу базы войти нельзя.

## Чего ещё нет

Это не «на будущее», а известные дыры — держите их в виду до закрытия.

1. **Мессенджер не работает между устройствами.** `connectSocket` в
   `src/messenger/socket.ts` — пустая заглушка, обмен идёт через
   `BroadcastChannel`, то есть только между вкладками одного браузера.
   WebSocket-хаб написан, проксируется через `/ws` и проверяет живую
   сессию, но клиент к нему не подключается, а сам хаб держит переписку
   в памяти процесса.

2. **Действия администратора выполняются в браузере.** Бан, выдача Prime,
   модерация правят localStorage. Права на админку подделать уже нельзя —
   они приходят из базы, — но и сами действия дальше браузера не идут.

3. **Контент — всё ещё локальный.** Лента, маркетплейс, объявления,
   подарки, семейный счёт живут в localStorage каждого браузера.

4. **Пополнение кошелька закрыто** (`PAYMENTS_MODE=disabled`). Открывать
   его можно только вместе с настоящим платёжным провайдером: иначе
   баланс рисуется одним запросом. По той же причине закрыты возврат
   средств, начисление баллов и покупка Prime — их источники (семейный
   счёт, активность пользователя, оплата) пока считаются в браузере.
   Само списание за Prime при этом уже делает сервер по своей таблице
   цен, так что при подключении оплаты останется заменить только вход
   денег, а не выдачу подписки.

5. **Загрузка файлов** идёт в IndexedDB браузера; серверного хранилища
   с проверкой типа и размера нет.

6. **Матчмейкинг в «Играх» имитируется локально** — сервера подбора нет.

## Что уже перенесено на сервер

- **Sky ID: вход и профили.** Вход по номеру телефона и коду из SMS;
  пароля больше нет. Внутри Sky ID — до двух профилей, и предел стоит
  триггером в базе, а не только в коде. У каждого профиля свои Prime,
  кошелёк и двухэтапная защита; защита самого Sky ID — отдельная и
  независимая. Секреты защиты лежат в базе зашифрованными
  (`ENCRYPTION_KEY`), коды одноразовые, счётчик попыток и пауза между
  отправками — на сервере.

  Факт входа и активный профиль сервер берёт из своей сессии, а не из
  токена: после «Выйти из Sky ID» подписанный токен перестаёт работать
  сразу, а не доживает свой срок. Права (`isAdmin`, `isPrime`) приходят
  из базы и перезаписывают локальные значения при каждой загрузке.

  Второй фактор — на выбор: код из приложения-аутентификатора или код
  письмом на подтверждённую почту. SMS вторым фактором нет намеренно:
  вход и так идёт по коду из SMS, и второй код на тот же номер ничего
  не добавляет — кто получил первый, получит и второй.
- **Кошелёк.** Баланс, баллы и журнал операций в PostgreSQL. Списание,
  перевод и обмен идут в транзакции с блокировкой строки, отрицательный
  баланс запрещён на уровне схемы. Владельца операции сервер берёт из
  токена — списать с чужого счёта нельзя даже подделав запрос.
